Checks while a file is edited
Someone writing a page sees what its schema requires, and what they broke, while they type rather than when the change is pushed.
A plugin for Obsidian over any instance. It runs the checks a release ships as a file is edited and marks what fails where it is written…
Why an editor at all

An instance is a folder of Markdown files. So is a vault.

What a vault lacks is what an instance's CI supplies after the edit: a reference that resolves, and no field its schema does not declare. The plugin says so while the edit is made, and implements no rule of its own.

Editor · Ids

An id is set once and locked

Every page carries an id that outlives its name. The plugin writes one on every new page and refuses an edit that changes or removes it.

Copy entity id copies it. Give this page a fresh id replaces it, once you confirm.

Editor · Markdown form

A note is written back in the one Markdown form

Obsidian's table editor pads every column the moment one cell is edited. The plugin writes the note back in the form the CI checks, when it is left or saved.

An edit that was undone leaves no diff at all.

Also in the editor

Four smaller things it does

A picture at the H1A profile's picture is drawn round at the start of its heading. One that is not square, is outside 256 to 1024 pixels or is over 300 KB fails by name.
The pin, in the status barIt says pin differs when the manifest names another checker release than the one bundled. The instance's CI stays the gate.
A failing row, tintedIn a Live Preview table, a row that fails is tinted, with its message as the tooltip.
A question's Rests onEach row reads its type and owner from its own cells, as the checks do, and completes within them.

What it does not do

It stops at the editor.

The gate a change has to pass is still the checks an instance runs in CI. And the writing rules are a judgment: no check reads them, here or anywhere. The brief puts them where the writing happens, and a person holds a page to them.

rests onconcept Ruleobjective Every gate an agent's work passes is held by a person
Getting it

The meta-model's tooling installs it

npx --yes 'github:companygraph/meta-model#semver:*'

Its menu's Obsidian plugin entry puts the newest release into the vault and switches it on. Run again, it updates the plugin and keeps its settings. The plugin is not in Obsidian's community directory.
