A shared vocabulary, extracted

CompanyGraph.

The meta-model for operating a company.

One place for what a company knows. Readable by humans, accessible to AI.

Robert Blust · Software Engineer & Architect

The hook

A company's knowledge lives everywhere — and nowhere.

Purpose, strategy, processes, roles, metrics, rules — scattered across wiki pages, spreadsheets, tickets, chat threads and people's heads.

Neither humans nor AI can rely on it. What if all of it were one graph both could read?

The convergence

Two companies. The same shape.

One with a payroll

People, groups, roles, a process with gates.

One company of one

One person. No group. No employees.

Nothing in common but needing to run. Neither knew about the other. Both ended up here:

One home per thinga role, a rule, a metric — each in exactly one place
Facts and reasoning togetherwhat holds, and why — not in two systems
Filed by what it isfindable without asking anyone
Every kind has a set shapeso nothing stays half filled in

Size changed how much got filled in. It never changed the shape.

The shape

One page per thing.

  • Plain words, not a databasenothing to install, nothing to log into
  • Its title is its nameyou refer to it the way you say it out loud
  • It grows with the companya thing that gains parts of its own keeps them with it
References

Everything cross-references — no dead links.

  • References are names — the canonical name of the entity, never a path.
  • Moving breaks nothing — nothing pointed at where the file was.
  • Renaming breaks loudly — a name that does not resolve is caught, not shipped.

No dead links — because there are no links.

The breadth

Everything that makes a company — in one vocabulary.

profilewho someone is
rolewho does what
processhow work flows, gate by gate
rulewhat we enforce
kpiwhat we measure
conceptwhat we define

Versioned like code, reviewed like code — one vocabulary for all of it.

A gate

Governance as data — not as a slide.

  • Who signs it offa named role — if it is vacant, there is no sign-off
  • The criterionthe proposal names the rules it touches
  • The rule behind itnothing gets built before the gate is signed off
  • What stops the work againwritten with the proposal, not afterwards
Two audiences

It pays twice — for people, and for agents.

For people

Onboarding by role. An answer to “who owns this?”

And one place where the answer is the same for everyone.

For agents

A context layer they can act inside.

Vision, strategy, process, rules — stated, not inferred.

One source — two audiences, and no drift between them.

The thesis

Markdown. Checked by agents.

  • The schemas are Markdown too — a table per type, in the same repository as the facts.
  • Written to a fixed shape — the same columns, the same type words, the same word for required.
  • Not a stage on the way to JSON Schema — a formal schema language would make the model something only a tool can read.

It shrinks the space an agent has to guess in — and states the guardrails.

Take it

Copy it into a repository of your own.

Nothing to install, nothing to run. A folder of Markdown files and the conventions that hold them together as one graph.

Not all of it is written yet — the roadmap says what is.
